In the [first post](/posts/how-we-build-yomizaka), I told the story of a pay stub shown on a phone, in a café. One document, one question.

But a property manager does not check one document. In Québec, many leases renew on the first of July, and when you manage a few hundred units, you do not want to upload them one by one.

That is where Yomizaka changes scale.

## A batch is a CSV and some files

We kept the tool everyone already has: a spreadsheet. One row per document, three columns. The file name, the check to run, and your own reference (the unit, the file). French column names work too, and a template downloads from the page.

```csv
file,check,reference
lease-4512-st-denis.pdf,compliance,4512-3
lease-4514-st-denis.pdf,compliance,4514-1
stub-applicant-17.pdf,authenticity,file-17
```

You drop the CSV and the documents together, in one move. Before anything starts, Yomizaka shows a preview row by row: what will be checked, what will be reused from a check already done, and what is refused, with the reason. A file named in the CSV but not uploaded, a check that does not exist, a duplicate row. And the cost, in audits, before you click. If the account cannot pay for all of it, the screen says so first, not halfway through.

Once started, the batch moves on by itself, a few documents at a time. A row that fails never stops the others. If the account runs out of credits on the way, the remaining rows pause with the reason, instead of failing one after another. At the end, you export the result as a CSV, one line per line of the original file, with what each became.

The administrator sets the limits: whether batches are open, how many rows at most (two hundred today), how many checks at once. They are settings in the database, not constants in the code.

## What we do not charge twice

In a batch of a hundred leases, there are always duplicates: the same PDF sent twice, a lease already checked last month. Orazaka's engine now recognises an identical file by its fingerprint, for the same version of the check, and returns the result already computed, without calling a model and without taking an audit. The result says which check it comes from.

And if a check fails on our side, the free audit or the credit goes back, once. We learned it the hard way: a test account saw its audit spent by a run that had failed. That can no longer happen.

## Word, and where a photo comes from

Many leases and contracts arrive as Word files, not PDFs. Yomizaka now accepts `.docx`: the text is what the check reads, and the file itself goes through the authenticity review, like a PDF. OpenDocument (`.odt`) follows.

For photos of documents, the review now shows where the picture comes from: the declared device and software, the date it was taken and the date it was last changed, and whether a GPS position was removed. Always as signals on three levels, observed, unusual, inconsistent, never as a verdict. A photo cropped on a phone is not a forgery.

## Where we are

I will be honest about the state of things. Batches run, with their tests against a real database. The Android app has its first test build, and iOS follows with the same code. API keys exist: a manager will be able to plug Yomizaka into their own software. The public API that goes with them, to start a check or a batch with a key, is being prepared.

We are starting to prepare a real demo for property managers. Not an edited video: a real batch, real test documents, and the screens as they are. The Québec rule set is still waiting for a lawyer's review, and the screen keeps saying so.

If you manage buildings and, on the first of July, you too have a pile of leases to reread, I would like to know how you do it today. Yomizaka is at [yomizaka.com](https://www.yomizaka.com).
